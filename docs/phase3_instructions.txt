`scaled_dot_product_attention(q, k, v, *, causal=False, mask=None)`

# PART C — MULTI-HEAD ATTENTION

## 6. Mathematical derivation

Include in the documentation the standard expression:

`MultiHead(Q,K,V) = Concat(head_1, ..., head_h) W_O`

where:

`head_i = Attention(Q W_Q^(i), K W_K^(i), V W_V^(i))`

Explain that an implementation may use three full-width linear projections followed by reshaping to obtain the per-head projections.

For the initial model:

`d_model = 128`

`n_heads = 4`

Therefore:

`d_head = d_model / n_heads = 32`

Define and enforce:

`d_model % n_heads == 0`

All dimensional assumptions must be documented and validated.

For Phase 3, use equal key and value widths per head unless there is a compelling, documented reason to support more complexity.

Explain why each head can learn a different projection of the same input representations.

Do not claim that heads have learned linguistic relationships before training.

## 7. Implement the MultiHeadSelfAttention module

Create:

`src/zaid_lm/multihead_attention.py`

Implement a reusable PyTorch module, e.g.:

`class MultiHeadSelfAttention(nn.Module)`

Expected constructor concept:

`__init__(d_model, n_heads, dropout=0.0, bias=True)`

You may refine the signature to work naturally with the existing `ProjectConfig`.

Required components:

1. Independent learned Q projection.
2. Independent learned K projection.
3. Independent learned V projection.
4. Explicit head splitting.
5. Explicit dimension permutation.
6. Per-head scaled dot-product attention.
7. Causal mask support.
8. Concatenation/merging of head outputs.
9. Learned final output projection.
10. An inspectable attention-weight return mechanism.

The model must not load pretrained weights.

All trainable weights must be initialized by the submitted implementation or PyTorch's standard layer initialization.

### 7.1 Input contract

Primary input:

`X.shape = (B, T, d_model)`

Validate dimensional consistency.

The output should be:

`Y.shape = (B, T, d_model)`

Attention weights should be accessible with shape:

`(B, n_heads, T, T)`

A clean return contract is:

`forward(x, *, causal=True, mask=None, return_attention=False)`

Prefer returning a single output tensor normally and `(output, weights)` when inspection is explicitly requested.

Choose one consistent interface and document it.

Do not silently change interface conventions between tests and experiment scripts.

### 7.2 Linear projections

Compute:

`Q = W_Q(X)`

`K = W_K(X)`

`V = W_V(X)`

Each initially has shape:

`(B, T, d_model)`

Use separate `nn.Linear` modules.

Do not share the three projection matrices by accident.

### 7.3 Split into heads

Transform each projection:

`(B, T, d_model)`

to:

`(B, T, n_heads, d_head)`

then permute to:

`(B, n_heads, T, d_head)`

Make the operation explicit in code.

Do not incorrectly reshape directly into `(B, n_heads, T, d_head)` without the necessary permutation.

Ensure the result preserves each token's feature grouping.

### 7.4 Attention within each head

Pass the reshaped Q, K and V to the verified Phase 2 function.

The resulting attention output must have shape:

`(B, n_heads, T, d_head)`

The attention weights must have shape:

`(B, n_heads, T, T)`

Apply the causal masking logic from Phase 2.

Do not introduce a second inconsistent causal-mask convention.

Attention-score scaling must use `sqrt(d_head)`, not `sqrt(d_model)`.

### 7.5 Merge heads

Permute:

`(B, n_heads, T, d_head)`

to:

`(B, T, n_heads, d_head)`

Then concatenate the head features into:

`(B, T, d_model)`

Use a safe contiguous reshape approach.

Explicitly prove that token order and head feature order remain correct.

### 7.6 Final output projection

Apply the output projection:

`W_O: d_model -> d_model`

The final output shape must be:

`(B, T, d_model)`

Demonstrate that the output projection is trainable and receives gradients.

### 7.7 Dropout

The assignment specifies configurable dropout for the future model.

Implement an explicit, well-documented dropout policy.

Output-projection dropout is acceptable. Attention-probability dropout may be supported only if its interaction with the existing Phase 2 engine is correctly designed.

Do not modify the Phase 2 attention probability output silently.

If probability dropout is implemented, clearly distinguish normalized pre-dropout attention weights from stochastic post-dropout weights; the latter need not sum to one.

For deterministic mathematical demonstrations, use evaluation mode or zero dropout.

Verify train/eval behavior.

### 7.8 Causal correctness

The final multi-head output at token t must be independent of tokens at positions greater than t.

This property must hold not only for returned attention weights but for the actual final output after head merging and output projection.

Write perturbation tests that modify future token representations while leaving the prefix unchanged.

Check earlier outputs remain invariant within justified numerical tolerance.

Check that attention weights for future positions are zero in every head.

# PART E — SINUSOIDAL POSITIONAL ENCODING

## 11. Implement positional encoding from scratch

Create:

`src/zaid_lm/positional_encoding.py`

Implement:

`class SinusoidalPositionalEncoding(nn.Module)`

Use the exact sinusoidal formulation:

`PE(pos, 2i) = sin(pos / 10000^(2i/d_model))`

`PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))`

Explain:

- `pos` is the token position.
- `i` indexes frequency pairs.
- Even feature indices use sine.
- Odd feature indices use cosine.
- Different dimensions vary at different frequencies.
- The representation depends on position rather than token identity.

Do not use learned positional embeddings as the required implementation.

Do not use external positional encoding packages.

### 11.1 Shape requirements

For an input with shape:

`(B, T, d_model)`

the positional encoding should be compatible with:

`(1, T, d_model)`

Adding it to the input must preserve:

`(B, T, d_model)`

Ensure sequence length does not exceed configured context length.

### 11.2 Configuration

Use the existing project configuration where appropriate:

`d_model`

`context_length`

`position_encoding = "sinusoidal"`

Do not change the existing character tokenizer proposal or unresolved vocabulary.

The positional encoding should not depend on the number of attention heads.

### 11.3 Correctness and implementation details

Support at least the currently proposed even model width.

If odd widths are supported, correctly handle the last unmatched frequency dimension and test it. Otherwise, explicitly validate and document the restriction instead of relying on accidental tensor-shape behavior.

Ensure:

- Position zero follows the sinusoidal formula.
- Different positions produce different encoding vectors where expected.
- The same position yields consistent values across runs.
- Encoding does not modify the input tensor in place.
- Device and dtype follow a documented policy.
- Evaluation does not introduce randomness.
- There are no trainable position parameters for the sinusoidal-only implementation.

Use an appropriate registered buffer if precomputing the positional table.

Ensure checkpoint and device-migration behavior is compatible with future model integration.

### 11.4 Dropout policy

If positional encoding includes dropout, make it configurable and test train/eval behavior.

Do not use active dropout when generating mathematical evidence.

Clarify whether the module:

- Returns positional vectors only, or
- Adds positional vectors to input representations.

Prefer an interface that is easy to integrate into Phase 4 without duplicating the addition.

### 11.5 Position offsets

If a future sequence offset is supported, validate it rigorously.

Do not implement speculative KV-cache functionality in this phase.

A simple start-at-zero position contract is acceptable for Milestone 2, with future extensions documented.
